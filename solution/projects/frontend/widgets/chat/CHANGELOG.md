# Changelog

## Next (not published)

- **Fix: the phone sheet's "Sign in" (or any navigation from inside the sheet) went to the new page and straight back.** An open layer pushes one history entry so Back closes it; closing it from inside (or unmounting it) popped that entry with `history.go(-1)` after 60 ms. When the page had navigated in between (`router.push('/auth')`), the entry on top was the new page, so the pop undid the navigation. `settleLayers(entries, current)` now pops only while the page is still on the layer's own entry, otherwise it forgets the dead entry and leaves the history alone (`primitives/layer/layer-registry.ts`, `core/screen/back-stack.ts`, tested). Found in gptkino ("Войти" in the assistant on a phone).

- **On a phone the assistant sheet closes when the pathname changes** (`ChatDock`, `AssistantFrame`; prop `closeOnNavigate`, default true). A query or hash change does not close it. Uses the new `usePathnameChange` of `@djangocfg/ui-core/hooks`, so it works with any router the host bridged; the widget imports nothing from Next.

- **`useSession` derives `payloadKinds` from `dataRenderers`.** New optional dep `dataRenderers` (the map the host already gives `AssistantChat`; only its keys are read). When `payloadKinds` is omitted, the kinds drawn are those keys plus the package's own blocks (`ask`, `approval`, `changes`; `BLOCK_KINDS` moved to `core`, still re-exported by `blocks`); an explicit `payloadKinds` wins; with neither, nothing is filtered, as before. A host deletes its second list (docman `PAYLOAD_KINDS`, reforms `kinds` memo).

- **`assertChatClient(openapi)` in `@djangocfg/widget-chat/testing`** (also `chatClientProblems`, `ChatClientDriftError`). A host calls it once in a test with its checked-in `openapi.json`; it throws one error listing every way the generated client is behind the server: a missing threads, messages, `stream`, `cancel`, part `ack` or attachments route, `ChatMessage` without `trace` or still with `tool_calls`, no `trace_step` frame schema. Paths are matched below the mount, so any mount and any operation ids pass, with or without a trailing slash. A host whose kinds take no files passes `assertChatClient(openapi, { attachments: false })` and is not asked for the upload route (gptkino). See `@docs/testing.md`.

- **A fenced block in an answer is the kit's `PrettyCode`.** `Response` mounts `@djangocfg/widget-kit/pretty-code` through a Streamdown `components.code` override (`content/code-block.tsx`, `ChatCode`) instead of the `@streamdown/code` shiki plugin, so the chat, widget-code and chat-dev share one highlighter, header, copy button and theme. Inline code and mermaid still go to Streamdown's default; the math and diagram plugins stay. A half-arrived fence renders the text so far, an open fence with no body keeps its header (`pending`). **Look changes:** lines wrap instead of scrolling sideways; the label reads "TypeScript" / "bash"; the copy button is always in the header (it says the chat's own `message.copy`); the surface is the `--code` token. **Removed:** the dependency `@streamdown/code` (about 14.8 MB of shiki grammars in the install; the `Response` entry is 587 KB to 493 KB minified, 397 lazy chunks gone). The chat already depended on `@djangocfg/widget-kit`; its new `./pretty-code` adds prism-react-renderer and prismjs (3.0 MB). Decision: `widgets/@dev/decisions/chat-code-block-is-the-kit-pretty-code.md`.

- **The Run block is lighter (Notion-style).** No card, border or coloured box; the header is "Worked for 10s" (a failed run: "Worked for 10s · 1 failed", destructive colour), the list is flat one-line steps. A step's words are the host's `labels`, the server's `label`, then a template by kind of work (`run.verb`: read, search, write, think, other) in 17 languages. **Removed, no alias:** the compact density (`RunOptions.density`, `remember`, `RunDensity`, the `data-density` attribute, `run.density`), the JSON export (`RunOptions.onExport`, `runToJson`, `run.export`), the visible toolbar row, per-step status and duration columns, the "N tools used" chip in the Run block. New words `run.worked`, `run.done`, `run.verb`; `run.thinking` is `run.verb.think.live`. Plan: `widgets/@dev/active/chat-reasoning-trace/PLAN.md`, "R3: lighter look".

- **The Run block** (`createRunRenderer`, `RunBlock`; opt-in through `renderers={{ run: ... }}`). Adjacent thoughts, tool calls and trace steps of a turn become one block: a quiet header ("Reading 3 emails… · 2 tools" while it works, then "Worked for 10s"), a flat list of one-line steps under a thin rule (icon, verb phrase, the object as an underlined chip when the server named it; no status column, no durations), a disclosure per step that has detail (why, query, arguments, result, sources, duration, tokens, cost, error), a thought in a bounded box faded at the top that follows the stream while live, failed or stopped steps that open the block and stay open with a red icon and the reason, one copy button (Markdown, built from what the screen shows) at the end of the opened list, pages of 25 with "Show N more" and a counted fold of the oldest settled steps past 200, and the note for steps a stored record dropped. Privacy fails closed: `argsMode`, `resultMode`, `maskPatterns`, `maxPreviewChars`, `labelsOnly` (public chats), `showReasoningText`; the client only narrows the server's redaction. The model is headless in `core/run/` (`selectRun`, `stepTitle`, `resolvePrivacy`, `detailOf`, `windowSteps`, `planRuns`, `runToMarkdown`, `stepPhrase`); `PartRenderProps.part` widens to `MessagePart | RunPart`; with no `run` renderer registered `MessageContent` is unchanged. New `run` section in the dictionary (17 languages), `styles/run.css`, `@docs/run-block.md`, stories `Widgets/Chat/Run`. Plan: slice R1.

- **The `trace_step` frame and the stored `trace` reach the transcript.** `wire/trace.ts` decodes TraceStep v1 and fails closed (unknown `status` is `skipped`; unknown or absent `redaction` is `omitted`, and an omitted step keeps no arguments, result, purpose, query or sources). A step becomes a `ToolPart`, a hidden `ReasoningPart`, or a `data` part of kind `trace` (`core/run/trace.ts`), all with `meta`; a new `step` chunk upserts it by id (an older `meta.eventSeq`, or a `running` frame after a settled one, is ignored). The stream adapter turns the frame into that chunk and seals the open thought and text at a new step. `fromStored` restores the stored `trace` ordered by `seq` before the words, with running steps settled to cancelled and a `note` for steps the document dropped. `StoredMessage.trace` is new and optional; `StepMeta` gains `model`, `tokens` and `costUsd`. The Python fixture is copied to `src/wire/fixtures/events-trace.json` (it includes the resume `run` frame), so the Python contract test no longer skips. Docs: `@docs/assistant-wire-contract.md`. Plan: slice R2.

- **Reasoning and tool calls are drawn by default in the assistant, and the reducer no longer leaves them open.** `AssistantChat` registers `reasoning` and `tool` next to `text`, `data` and `attachment` (before, a thought or a call that reached the transcript drew nothing unless the host passed `renderers`). The reducer (`core/transcript.ts`, `core/settle.ts`): a repeated `text-start` / `reasoning-start` / `tool-input-start` is idempotent by id; tool chunks that arrive before their start are buffered (16 calls x 16 chunks) and applied on it; the first answer a call gets is final; `finish`, `error` and `interrupted` seal an open thought and turn an open call into `output-error` with `meta.status: "cancelled"` (a Stopped call, not a failed one, and never running forever). Rendering: `groupParts` now has a consumer. `planFold` (`core/group-parts.ts`) and the `ToolFold` primitive fold two or more settled successful calls into one closed counter, "N tools used"; nothing folds while a call runs, and a call that failed, timed out or was stopped stays visible. New optional `ToolPart.meta` and `ReasoningPart.meta` (`StepMeta`, `StepStatus`, `StepRedaction`, `StepRef`) and the render-only `RunPart`; absent for every existing producer. New words `tool.cancelled` and `tool.used` in 17 locales. Stories `Widgets/Chat/Tool Call/Folded` and `Stopped`. Plan: `widgets/@dev/active/chat-reasoning-trace/PLAN.md`, slice R0.

## Carried over from `@djangocfg/widget-assistant` (its unpublished notes, as they stood on 2026-11-10)

Paths in these notes are the old ones: `stream/`, `sessions/`, `composer/` and `messages/` are now under `session/`, `shell/` and `assistant/history/`, and `@djangocfg/widget-assistant` is `@djangocfg/widget-chat/assistant`. Story titles `Widgets/Assistant/...` are `Widgets/Chat/Assistant/...`.

- **Chat attachments from the server (django-cfg `chat.attachments`).** `loadChatAttachments({ calls, kind?, messages? })` builds the composer's `attachments` capability from `GET attachments/limits/` and the generated multipart upload (resolves `undefined` when the kind takes no files); `ChatUploadError` carries the status and problem code. The default send body now sends `attachments: [{id}]` only (was the full objects: **breaking for a custom server that read `url` or `name` from it**). Stored messages with files become `attachment` parts (`StoredMessage.attachments`, `ChatMessageShape.attachments`); a file alone is not a hidden feedback turn. New reject codes `too_large` (413) and `unsupported_type` (415) with two words in all 17 dictionaries (`errTooLarge`, `errUnsupportedFile`). Fixture `src/wire/fixtures/attachments.json`. `StoredAttachment.expired`: a file whose bytes the server deleted (retention) comes back with an empty `url` and is drawn as a muted chip.

- **One complete assistant in Storybook, and the model aliases are localized (breaking).** `Widgets/Assistant/Complete` (Default, Empty, Dock, Sheet) is the single fixture with everything on; `Widgets/Assistant/States` keeps only failure and edge states; `Layouts/Notion shell` reuses the same fixture through `useDemoAssistant`. The duplicate demo stories are gone. `DEFAULT_MODEL_ALIASES` is replaced by `useModelAliases(locale?)` (six new words, `modelAuto`..`modelSmartHint`, in all 17 dictionaries); ids stay `auto` / `fast` / `smart`. Approval and undo replies to the agent are fixed English in the chat (`BLOCK_REPLY`), so the agent's prompt does not depend on the reader's language.

- **Blocks, picture lightbox and model switch from the chat** (see its `@docs/blocks.md`): `ask` / `approval` / `changes` data parts are drawn with no registration; the demo's own `approval` and `choices` widgets are removed (`choices` payloads become `ask`; `approval` keeps its shape). An attached picture opens in the lightbox. New `AssistantChat models`, `DEFAULT_MODEL_ALIASES`, `DEFAULT_MODEL`, `SendInput.model` (sent as `model` in the default body only when set), and the block components re-exported. **Breaking for a host that registered `approval` or `choices` under `dataRenderers`:** a host entry still wins for its kind, but the chat now draws the same kinds by default.

- **`AssistantMenu` removed (breaking).** The widget draws no menu of its own: `SessionsMenu` has a free `children` slot after its buttons, and a host builds its "..." menu from UI Core's `MenuBuilder` (`MenuItem[]`) there or in `actions`. `AssistantMenuItem` / `AssistantMenuProps` are gone. `SessionsMenu` buttons are plain UI Core `Button`s (`ghost`, `icon`), not the round `PanelIconButton`.

- **History is a screen, not a dropdown.** `SessionsPanel` is drawn over the conversation (the chat stays mounted, so a run keeps streaming): a New chat row, chats grouped Today / Yesterday / by month (headings from `Intl`), a search field from seven chats, the open chat marked. New: `AssistantHistory`, `useAssistantHistory`, `SessionsPanel`, `groupSessions`, `filterSessions`; `AssistantSlot` draws the screen. **Breaking:** `SessionsMenu` no longer has the dropdown list; its second button toggles the screen and needs `AssistantHostProvider` (without it only "New chat" shows). Hosts with their own `ChatMenu` replace the list of chats with one "History" row (`setOpen(true)`). Three new words in all 17 locales (`sessionsSearch`, `sessionsNoMatch`, `sessionsBack`).

- **Attachments passed through.** `AssistantChat attachments` (merged into `capabilities.attachments`), the `attachment` part drawn by `AttachmentRenderer`, `SendInput.attachments` forwarded by the default body as `attachments`, and the chat's attachment types re-exported (`AttachmentsCapability`, `AttachmentKind`, `Attachment`, defaults) so an embedder configures it from this package. The widget sets no default capability: attaching needs the host's `upload`.

  - `AssistantFrame`: `heading` (replaces the title in the header: a segment control, a count), `help` (`false` leaves the `?` out, a node replaces it), `tablet` (`window` | `sheet` from 768 px), `windowBottom` (the floating window starts above a host's bottom bar), `stageMin` (the page keeps at least that many px; the column's limit is `min(maxWidth, viewport - stageMin)`, the remembered width is not rewritten), `className`, `fill` (the frame fills a box the host sized). `ChatDock` takes `heading`, `help`, `tablet`, `windowBottom`.
  - `AssistantChat`: `store` (a host-fed transcript, fed with `store.receive`), `capabilities`, `renderers`, `footer` (a row under each message), `composer: { compact }`, `readOnly` (replaces the composer for a viewer who cannot post); `suggestions` is optional. `MessageFooter` takes `children`; another participant's line is left-aligned.
  - `AssistantHelp rows` / `useHelpRows` (the Help list as data), `useViewportWidth`, `columnLimit`, and the exports `DOCK_FROM`, `DICTATION_TOGGLE`, `MessageFooter`.
  - New entry `@djangocfg/widget-assistant/shell`: the frame, dock, host trio, menu, chat body and panel state without the SSE wire, the sessions and the demo, for a host whose transport is its own.
