# Built-in Apps

django-cfg registers its own Django apps in `INSTALLED_APPS` and mounts their URLs under `/cfg/`.
You do not list them in `project_apps`. Some are always on; the rest are switched on by a field of
`DjangoConfig`. They are part of the package (`django_cfg.apps.*`), not files in your project, so
you configure them through the config and extend them through settings and signals.

## Always on

| App | Module | What it does |
|-----|--------|--------------|
| **Accounts** | `django_cfg.apps.system.accounts` | OTP login, JWT, OAuth, API keys, profiles, login alerts, brute-force protection |
| **TOTP** | `django_cfg.apps.system.totp` | Two-factor authentication |
| **Mailer** | `django_cfg.apps.system.mailer` | Per-locale letter copy and the send log |
| **Health, Commands** | `django_cfg.apps.api.health`, `django_cfg.apps.api.commands` | Health endpoints and the management-command API |

Accounts, TOTP and the mailer are inserted before `django.contrib.admin` so their migrations run first.

## Switched on by a config field

| Config field | App |
|--------------|-----|
| `currency` | `django_cfg.apps.tools.currency` |
| `geo` | `django_cfg.apps.tools.geo` |
| `analytics` | `django_cfg.apps.tools.analytics` |
| `chat` | `django_cfg.apps.tools.chat` |
| `payments` | `django_cfg.apps.payments` |
| `simple_history` | `simple_history` |
| `mcp`, `notion`, `django_rq` | the matching `django_cfg.modules.*` module |

Each field takes a config object with `enabled`; see [Tools](/features/tools) and the
[module pages](/features/modules).

## Project extensions

Code that lives in your project goes in [Extensions](/extensions): a folder under
`extensions/apps/` with a `__cfg__.py` file, discovered automatically. That mechanism is separate
from the built-in apps above.

## User management

[User Management](/features/built-in-apps/user-management) covers the accounts and TOTP apps, which
most projects use first.
