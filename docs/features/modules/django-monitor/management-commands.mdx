# Management Commands

## `monitor_status`

```bash
python manage.py monitor_status
```

Reports:

- Whether monitoring is enabled (it always is — zero-config).
- Whether **Telegram alerts** are on, i.e. whether a `TelegramConfig` is present
  on your `DjangoConfig`.
- Where events go: `<log dir>/djangocfg/monitor.log` with a summary of today's
  captured events when `DJANGO_CFG_LOG_DIR` is set, otherwise `stdout`.

<Callout type="info">
Retention is handled outside the app: `monitor.log` is a plain file that
`logrotate` rotates (django-cfg reopens it). There is no separate cleanup command
to run. Without `DJANGO_CFG_LOG_DIR`, events are JSON lines on stdout.
</Callout>

## `monitor_tail`

Print the last events from `monitor.log`, no docker and no grep.

```bash
python manage.py monitor_tail                   # last 20 events
python manage.py monitor_tail -n 50 --frontend  # last 50 browser events
```

One line per event: time, `frontend` or `server`, level, event type, message, page URL. `--frontend` keeps only what arrived through `POST /cfg/monitor/ingest/` (all levels, including the `devtools ping` from `window.devtools.ping()`). Without a log directory it says so and you read the container log. Nothing is stored by the command.
