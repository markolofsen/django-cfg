# Frontend devtools — `@djangocfg/devtools`

`@djangocfg/devtools` is the browser counterpart to [`django_monitor`](/features/modules/django-monitor).
One package, one event stream:

- **Capture** — `window.onerror`, unhandled promise rejections, `console.warn` /
  `console.error`, and zod validation events from `@djangocfg/api` clients.
- **Ingest** — errors and warnings are batched to `POST /cfg/monitor/ingest/`
  (handled by `django_monitor`) with dedupe, a keepalive flush on page unload,
  and a circuit breaker that backs off if the endpoint is failing.
- **Debug panel** — a floating button (automatic in development, `?debug=1` in
  production, or ⌘D) opening a filterable log feed plus any app-defined custom
  tabs.

<Callout type="info">
`@djangocfg/devtools` replaces the retired `@djangocfg/monitor` and
`@djangocfg/debuger` packages — a single dependency in place of the old pair.
</Callout>

## Setup

Mount `<Devtools>` once in your root layout — that is the entire setup:

```tsx
import { Devtools } from '@djangocfg/devtools'

export default function RootLayout({ children }) {
  return (
    <html>
      <body>
        {children}
        <Devtools project="my-app" environment={process.env.NODE_ENV} />
      </body>
    </html>
  )
}
```

Capture starts on mount, and ingest posts to `/cfg/monitor/ingest/` on the
API origin. **The origin must be known**: `devtools={{ baseUrl }}`, or in
`BaseApp` the `auth.apiUrl` (derived automatically), or `apiUrl` for an
`auth={false}` public app, or `NEXT_PUBLIC_API_URL` at build time (in turbo it
must be listed in `env`, an undeclared variable is `undefined` in the client
bundle). With none of them, ingest is on but nothing can be sent: devtools
logs one console warning naming the fix, and `window.devtools.status()` shows
`baseUrl: ''`.

```tsx
<BaseApp project="site" auth={false} apiUrl={process.env.NEXT_PUBLIC_API_URL}>
```

Precedence: `devtools.baseUrl`, then `apiUrl`, then `auth.apiUrl`, then `NEXT_PUBLIC_API_URL`.

## Imperative API

```ts
import { devtools } from '@djangocfg/devtools'

// Goes to both the panel feed AND the backend ingest:
devtools.error('Payment widget crashed', { orderId })

// Component-scoped local logger — panel feed only, never sent to the backend:
const log = devtools.log('CheckoutForm')
log.info('step changed', { step })
```

In the browser console the same API is available as `window.devtools`
(`window.devtools.status()`, `window.devtools.error('test')`).

### Check that it reaches Django

- `window.devtools.status()` returns `{ ingest, baseUrl, queued, sent, failed, lastError, lastSentAt, circuitOpen }`
  (and prints it): `failed > 0` with `lastError` says why, `circuitOpen` means ingest is paused for
  60 s after three failed sends.
- `await window.devtools.ping()` sends one `info` event, `devtools ping`, now, and resolves with
  `status()`. django_monitor logs it and never alerts on it.
- On the server: `python manage.py monitor_tail --frontend` shows it
  ([management commands](/features/modules/django-monitor/management-commands)). Browser events are
  logged at every level (`monitor.log`, logger `django_cfg.monitor.frontend`), not only errors;
  `grep FRONTEND` finds nothing because the event types are `JS_ERROR`, `WARNING`, ...

## Server-side reporting

For route handlers and React Server Components, the server entry reports errors
straight to the ingest endpoint:

```ts
import { serverDevtools } from '@djangocfg/devtools/server'

serverDevtools.configure({ project: 'my-app', baseUrl: process.env.API_URL })
await serverDevtools.captureError(err, { url: req.url })
```
