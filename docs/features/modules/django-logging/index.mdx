# Django Logging

Django-CFG logs the Django / 12-factor way: **records go to stdout/stderr and the platform routes them** (Docker, systemd, your terminal). The app does not manage log files unless you ask for one. Importing `django_cfg` creates no directories, writes no files and does not touch your root handlers.

## Features

- **stdout by default** — no `logs/` folder in the project tree
- **File is opt-in** — `DJANGO_CFG_LOG_DIR` or `DjangoConfig(logging=...)`; `WatchedFileHandler`, so `logrotate` owns rotation
- **Text or JSON** — `DJANGO_CFG_LOG_FORMAT=json` writes one object per line, for containers
- **Your `LOGGING` wins** — django-cfg only generates the `LOGGING` dict; override it in the project as usual
- **Sanitized extra context** — reserved `LogRecord` attributes in `extra={}` are prefixed with `ctx_`

## Quick Start

```python
from django_cfg.modules.django_logging import get_logger

logger = get_logger("django_cfg.myapp")

logger.debug("Processing started")
logger.info("User created", extra={"user_id": 42})
logger.warning("Rate limit approaching", extra={"endpoint": "/api/users"})
logger.error("Payment failed", extra={"order_id": "ORD-123"})
```

`get_logger()` automatically detects the caller's file path to build the logger name when called without arguments from within `django_cfg` code:

```python
# In a file at django_cfg/modules/my_module/service.py
logger = get_logger()
# auto-resolves to: django_cfg.my_module (or similar based on path)

# Explicit name
logger = get_logger("django_cfg.payments.stripe")
```

<Callout type="info">
`get_logger()` rewrites a name that doesn't start with `django_cfg` based on the
**caller's** file path. To be certain which logger an event lands on, pass a
fully-qualified name (`get_logger("django_cfg.payments.stripe")`).
</Callout>

## Where logs go

| You set | Result |
| --- | --- |
| nothing | stdout/stderr only; `django_cfg` at `WARNING` (`DEBUG` when `debug=True`) |
| `DJANGO_CFG_LOG_DIR=/var/log/myapp` | also `django.log` and `djangocfg/monitor.log` in that directory |
| `DJANGO_CFG_LOG_FILE=1` | file in the per-user log dir (`platformdirs.user_log_dir(project)`) |

The directory is created when the first record is written, not at import. If it cannot be written, django-cfg logs one warning and keeps logging to stdout.

Precedence for the log directory: config `logging.log_dir`, then `DJANGO_CFG_LOG_DIR`, then the default (none). `project` in the per-user paths is the top package of `DJANGO_SETTINGS_MODULE`, else the working directory name, so projects on one machine do not share state.

## Configuration

```python
from django_cfg import DjangoConfig, DjangoLoggingConfig

class Config(DjangoConfig):
    logging: DjangoLoggingConfig = DjangoLoggingConfig(
        level="INFO",          # django_cfg loggers; default WARNING, DEBUG with debug=True
        format="json",         # "text" (default) or "json"
        log_dir="/var/log/myapp",  # None = stdout only
    )
```

| Field | Type | Default | Description |
| --- | --- | --- | --- |
| `level` | `str \| None` | `None` | Level of the `django_cfg` loggers |
| `format` | `"text" \| "json"` | `"text"` | `json` is one object per line |
| `log_dir` | `str \| None` | `None` | Write log files here. `None` = stdout only |

### Environment variables

| Variable | Meaning |
| --- | --- |
| `DJANGO_CFG_LOG_DIR` | Directory for log files (turns file logging on) |
| `DJANGO_CFG_LOG_FILE` | `1` = log to a file in the per-user log dir |
| `DJANGO_CFG_LOG_FORMAT` | `text` (default) or `json` |
| `DJANGO_CFG_LOG_LEVEL` | Level of the `django_cfg` loggers |
| `DJANGO_CFG_LOG_ROTATE` | `1` = rotate daily inside the process (`TimedRotatingFileHandler`, 30 days) |
| `DJANGO_LOG_TO_TMP` | Deprecated and ignored. Logs one warning. The `/tmp/djangocfg/debug.log` mirror is gone |

<Callout type="warning">
`DJANGO_CFG_LOG_ROTATE=1` is for a single process only. With several workers the
processes race on rollover and lose lines. Prefer the default `WatchedFileHandler`
plus `logrotate`, or no file at all.
</Callout>

### Removed fields

`enabled`, `file_enabled` and `file_rotation_days` were never read. `DjangoLoggingConfig` still accepts them (and ignores them with one warning) for one release. `django_cfg.LoggingConfig` is a deprecated no-op shim, removed in the next release.

## Upgrading from the `logs/` folder

For one release, if no override is set and `./logs` already exists in the working directory, django-cfg keeps writing there and logs **one warning** that names `DJANGO_CFG_LOG_DIR`. To keep the old location, set it explicitly. The next release drops the fallback. See the [CHANGELOG](https://github.com/markolofsen/django-cfg/blob/main/CHANGELOG.md) for the full note.

## Public API

### `get_logger(name="")`

Returns a standard `logging.Logger`. It adds no handlers.

```python
from django_cfg.modules.django_logging import get_logger

logger = get_logger("django_cfg.payments")
```

### `sanitize_extra(extra)`

Prefixes any key in `extra` that conflicts with Python's reserved `LogRecord` attributes (e.g., `module`, `message`, `name`) with `ctx_` to prevent `KeyError`.

```python
from django_cfg.modules.django_logging import sanitize_extra

safe = sanitize_extra({"module": "myapp", "user_id": 42})
# {"ctx_module": "myapp", "user_id": 42}

logger.info("Event", extra=safe)
```

### `clean_old_logs(days=30, logs_dir=None)`

Deletes log files older than `days` from the log directory (default: the resolved one). Returns `{"deleted": 0, "bytes": 0, "error": ...}` when there is no log directory. Not needed with `logrotate`.

```python
from django_cfg.modules.django_logging import clean_old_logs

stats = clean_old_logs(days=7)
# {"deleted": 12, "bytes": 45678, "human_readable": "0.04 MB"}
```
