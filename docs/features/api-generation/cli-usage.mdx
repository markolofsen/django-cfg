# CLI Usage

Client generation is one management command, `python manage.py gen`. It reads a
`generation.py` file that sits next to `manage.py`, runs the pipeline (drf-spectacular,
tag slicing, then the external generator for each language) and writes every client straight
into the `path` of its target. There is no separate validation command and no archive step.

## `gen`

```bash
python manage.py gen
```

Groups come from your `openapi_client` config (see [Group Configuration](./groups)); targets
come from `generation.py` (see [Code Generation](/cli/commands/codegen)).

| Flag | Description |
|------|-------------|
| `--config PATH` | Path to `generation.py` (default `./generation.py`) |
| `--ts`, `--py`, `--go`, `--swift` | Generate only for that language |
| `--target`, `-t TYPE` | Only targets of that type: `admin`, `web`, `packages`, `sdk`, `parsers`, `extensions` |
| `--groups NAME [NAME ...]` | Only these groups |
| `--dry-run` | Print what would be generated, write nothing |
| `--list-targets` | Print the configured targets and exit |
| `--check-stamp` | Write nothing; fail when a generated client's CFG contract differs from the installed django-cfg |
| `--verbose` / `--quiet` | More or less output |

```bash
python manage.py gen                          # all targets
python manage.py gen --ts                     # TypeScript only
python manage.py gen --groups core shop       # two groups
python manage.py gen --target web --ts        # web targets, TypeScript only
python manage.py gen --dry-run                # plan only
python manage.py gen --list-targets
python manage.py gen --check-stamp            # CI: are the clients current?
```

The command exits non-zero when a target fails, so it is safe in CI.

## Minimal setup

```python
# api/config.py
from django_cfg import DjangoConfig, OpenAPIClientConfig, OpenAPIGroupConfig

class CryptoConfig(DjangoConfig):
    openapi_client: OpenAPIClientConfig = OpenAPIClientConfig(
        enabled=True,
        groups=[
            OpenAPIGroupConfig(name="core", apps=["users", "accounts", "api_keys"], title="Core API"),
            OpenAPIGroupConfig(name="trading", apps=["wallets", "orders", "transactions"], title="Trading API"),
        ],
    )
```

```python
# generation.py (next to manage.py)
from pathlib import Path
from django_cfg.modules.django_generator import Config, OpenAPI, Target, Language, TargetType

FRONTEND = Path(__file__).parent.parent / "frontend"

config = Config(
    openapi=OpenAPI(
        targets=[
            Target(
                lang=Language.TYPESCRIPT,
                type=TargetType.WEB,
                path=FRONTEND / "src" / "api" / "generated",
                groups=["core", "trading"],
            ),
        ],
    ),
)
```

TypeScript extras (Zod schemas, fetchers, SWR hooks, SSE streams) are switched on or off in
`OpenAPIClientConfig`; see the [parameter table](./overview#openapiconfig-parameters).

## External tools

The generators are external programs: Hey API (TypeScript, run through `npx`, Node 18+),
`openapi-python-client`, `ogen` (Go) and `swift-openapi-generator` (Swift). Install the Python
side with `pip install "django-cfg[gen]"`. A missing tool fails the target that needs it.

## Cache and parallelism

A run with unchanged serializers, views and URLs is served from a two-layer cache. Targets run
in parallel.

| Variable | Effect |
|----------|--------|
| `DJANGO_CFG_GEN_NO_CACHE=1` | Skip both cache layers |
| `DJANGO_CFG_GEN_PARALLELISM=N` | Worker count (default `min(8, cpu_count, target_count)`) |
| `DJANGO_CFG_GEN_QUIET=1` | Silence per-target output |

## CI

```yaml
- name: Generate API clients
  run: python manage.py gen

- name: Fail if generated clients are stale
  run: git diff --exit-code frontend/src/api/generated
```

`python manage.py gen --check-stamp` is a cheaper gate when you only need to know that the
committed clients were produced by the django-cfg version you have installed.

## Best practices

- Commit the generated code, so a review shows what an API change does to the clients.
- Use groups to keep each client small; five to ten apps per group is a good size.
- Put output paths in named constants at the top of `generation.py`.
- Use `--dry-run` or `--list-targets` before the first run to check the paths.
