# Using Generated Clients

After generating clients with `python manage.py gen`, you'll have type-safe TypeScript, Python, Go, and Swift clients ready to use in your applications.

## TypeScript Clients

### Installation

A TypeScript target is written into the `path` of its `Target` in `generation.py`. The pinned Orval target produces one shared generated tree with `tags-split` endpoint modules, model/Zod schemas, React Query v5 hooks/query keys, and MSW handlers. The handwritten Fetch mutator/runtime stays outside the disposable generated directory.


<Callout type="info">
**Group Organization**

Each group listed in the target selects OpenAPI tags and becomes a split module inside the same target tree; schemas, query infrastructure, and authentication runtime are shared. A separate deployable client requires a separate `Target`.

</Callout>

#### Put it where the app imports it

Point `Target.path` at the folder your app imports from (for example `src/api/generated`); `gen` writes there directly, so nothing is copied by hand.

#### Install as NPM Package

Create a package:

```json
// package.json
{
  "name": "@myorg/api-client",
  "version": "1.0.0",
  "main": "index.ts",
  "types": "index.ts"
}
```

Then install locally or publish to NPM.

### Basic Usage

```typescript
import { useGetUser } from '@api/generated';

export function UserCard({ id }: { id: number }) {
  const { data: user } = useGetUser(id, {
    query: { staleTime: 60_000 },
  });
  return <span>{user?.name}</span>;
}
```

### Authentication

The generated operations delegate transport and authentication to the
handwritten `@djangocfg/api` mutator/runtime boundary. Applications use the
stable package auth/session exports; the disposable Orval tree must not become
a second token store.

- **Auto-refresh** — when the target's API exposes the SimpleJWT refresh
  endpoint (`/cfg/accounts/token/refresh/`), the client registers a default
  refresh handler at import time. A 401 transparently refreshes and retries —
  no app wiring needed. Override with `auth.setRefreshHandler(...)` if your
  backend differs.
- **Shared session** — all generated target slices use the same application
  auth/runtime boundary, so refresh and cache invalidation do not diverge by
  group.

#### Session (login / logout)

```typescript
import { auth } from '@djangocfg/api';

// The ONE write path after any login flow (atomic pair + notification):
auth.setSession({ access, refresh });

// Logout:
auth.clearSession();

// exp-aware check (expired access + live refresh still counts as logged in):
auth.isAuthenticated();
```

#### Storage modes

The runtime owns token storage and exposes one session store to all generated
operations. Do not configure storage separately for each group or generated
target:

```typescript
import { auth } from '@djangocfg/api';

auth.setSession({ access, refresh });
const token = auth.getToken();
```

The default runtime uses the configured CFG cookie/session policy. If an app
needs a different persistence policy, configure the application auth package;
never add a second token store inside generated code.

<Callout type="info">
Session length is the server's refresh-token lifetime — see
[Session Length](/features/built-in-apps/user-management/accounts/otp#session-length).
</Callout>

#### Other storage keys

Use the stable `@djangocfg/api/storage` and `@djangocfg/api/auth` exports when
an integration needs framework storage or session state. Do not import a
generated helper or read token keys directly from browser storage.

#### React — subscribe to the session

```tsx
import { useSyncExternalStore } from 'react';
import { auth } from '@djangocfg/api';

const session = useSyncExternalStore(
  auth.subscribe,
  auth.getSnapshot,
  auth.getServerSnapshot,
);
const isAuthenticated = session.status === 'authenticated';
// (@djangocfg/api exports this as the `useSession()` hook.)
```

#### Terminal 401 (session died)

```typescript
// Fires ONLY when the refresh path is exhausted. The store has already
// cleared the session — the handler just routes to login. Returns an
// unsubscribe function; multiple handlers compose.
const unsubscribe = auth.onSessionExpired(() => {
  window.location.replace('/auth');
});
```

#### API Key

```typescript
// Set API key (sent as X-API-Key)
auth.setApiKeyPersist('your-api-key');
```

#### Context headers and a hand-written `fetch`

Every request the generated client makes carries `Accept-Language`, `X-Timezone`, `X-Client-Time` and `X-Client-Id` (a random per-browser id, optional: SSR and crawlers send none; the server reads it as `request.client_id`, see [ClientIdMiddleware](/core/middleware#clientidmiddleware)). A request that does not go through the client (an SSE stream, an upload) gets none of them: spread `auth.clientHeaders()` from `@djangocfg/api` into its headers. The chat widget does this for its stream.

#### Custom request headers and CORS

The generated client already sends headers the default CORS list covers (`Authorization`, `X-API-Key`, `X-Timezone`, `X-Client-Time`, `X-Client-Id`, `X-Auth-Retry`, the chunked-upload headers, `Idempotency-Key`). If your app adds its own (`X-Holder`, `X-Content-SHA256`, ...) through a custom `fetch` or interceptor, no backend setup is needed: a preflight from an already-trusted origin gets the requested headers back. To list one explicitly set `cors_extra_headers = ["x-holder"]`; see [Custom request headers](/configuration/security#custom-request-headers). A browser "CORS error" with only `OPTIONS 200` in the server log means the preflight was refused: [how to read it](/configuration/security#reading-an-opaque-cors-error).

#### Public operations and sign-in steps — from the spec

Each generated call carries the facts the spec states about its operation, and the runtime acts on them:

- **No credentials accepted** (`security: [{}]`, or no `security` at all in a document without a global one):
  the call is sent with `auth: 'none'`. No `Authorization` header from the session, no refresh on a 401, and a
  401 never signs the user out. A logged-in user's token does not reach public endpoints. Optional auth (a session
  is used when there is one) gets no flag.
- **Sign-in steps** (password login, OTP request and verify, the OAuth callbacks, 2FA verify): `skipAuthRefresh:
  true`, because a 401 there is a wrong code or password, not an expired session. A view of your own marks one with
  `@extend_schema(extensions=SIGN_IN_STEP)` from `django_cfg.core.contract`.

Every operation takes `DjangoRequestInit` as its last argument, and every query and mutation hook takes it as
`request`, so a caller can set or override a flag for one call:

```typescript
await cfgAccountsProfileRetrieve({ signal });
const profile = useCfgAccountsProfileRetrieve({ request: { origin: 'direct' } });
```

#### Target options (TypeScript)

| Option | Default | Effect |
|--------|---------|--------|
| `auth_mode` | `"default"` | `"public"`: every request of this client goes without the session (`auth: 'none'`), and callers cannot turn it back on. For a client of public endpoints only. |
| `direct_origin_tags` | `[]` | OpenAPI tags whose operations go straight to the API host (`NEXT_PUBLIC_API_URL`), never through the proxy. A tag the target does not contain stops generation. |
| `infinite` | `False` | Also generate `use<Op>Infinite` and `get<Op>InfiniteQueryOptions` for every GET that takes a `page` (or else `cursor`) query parameter. Other GETs are unchanged. |

With `infinite=True`, the generated hook pages through the `page` (or `cursor`) parameter, but TanStack also needs
`initialPageParam` and `getNextPageParam`, which the generator does not write. Spread the runtime's page params for
the django-cfg envelope:

```typescript
import { drfCursorParams, drfPageParams } from '@djangocfg/api';

const pings = useRealtimeDemoPingsListInfinite({ page_size: 20 }, { query: { ...drfPageParams } });
// pings.data?.pages: one page envelope per fetch; pings.fetchNextPage() follows next_page.

// A cursor list (a `cursor` query parameter and `next_cursor` in the body):
const comments = useCommentsListInfinite({ object_id }, { query: { ...drfCursorParams } });
```

An infinite query has its own key, starting with `'infinite'`. A mutation that changes the list invalidates both:
`getRealtimeDemoPingsListQueryKey(params)` and `getRealtimeDemoPingsListInfiniteQueryKey(params)`.

```python
Target(
    lang=Language.TYPESCRIPT,
    type=TargetType.WEB,
    path=FRONTEND / "packages" / "catalog-api" / "src" / "generated",
    groups=["catalog"],
    direct_origin_tags=["listings", "api_keys"],
)
```

### Enum names

Each OpenAPI enum becomes a named TypeScript `enum` plus a zod schema. A
`TextChoices` class on a model is named after the class (`OAuthProviderEnum`).
An enum that comes from a plain `Enum` or a hand-written `ChoiceField` is named
after the field (`ErrorEnum`, `StatusEnum`), which collides as soon as two
fields share the name and then gets a hash suffix that changes between runs.
Pin such a name in `SpectacularConfig.enum_name_overrides`; the value is a
dotted path to a `TextChoices` class or to a callable returning `(value, label)`
pairs identical to the field's `choices` (labels are part of the match):

```python
SpectacularConfig(
    enum_name_overrides={
        "PaymentErrorCodeEnum": "myapp.payments.codes.payment_error_choices",
    },
)
```

`python manage.py suggest_enum_overrides` prints a working dictionary for every
hash-suffixed name. django-cfg pins its own: `OAuthErrorCodeEnum` (the `error` of the
OAuth endpoints, since 2.3.367).

### Multiple Groups

Groups are modules in one generated target, not separate API client instances.
Import the generated endpoint barrel once and let the shared runtime handle
authentication for every operation:

```typescript
import {
  cryptoCoinsList,
  useCryptoCoinsList,
} from '@api/generated/endpoints';

// Server Component or non-React code
const coins = await cryptoCoinsList({ page: 1 });

// Client Component
const query = useCryptoCoinsList({ page: 1 }, {
  query: { staleTime: 60_000 },
});
```

### React Integration

```typescript
import { useQueryClient } from '@tanstack/react-query';
import {
  getCryptoCoinsListQueryKey,
  useCryptoCoinsList,
} from '@api/generated/endpoints';

function WalletList() {
  const queryClient = useQueryClient();
  const { data, isPending, error } = useCryptoCoinsList({ page: 1 });

  if (isPending) return <div>Loading...</div>;
  if (error) return <div>Could not load coins.</div>;

  return (
    <ul>
      {data?.results.map(coin => (
        <li key={coin.id}>{coin.symbol}: {coin.name}</li>
      ))}
    </ul>
  );
}

// Mutations invalidate the generated key; do not invent string keys.
queryClient.invalidateQueries({
  queryKey: getCryptoCoinsListQueryKey({ page: 1 }),
});
```

### Error Handling

```typescript
import { APIError, NetworkError } from '@djangocfg/api';

try {
  const coins = await cryptoCoinsList({ page: 1 });
  console.log(coins.results);
} catch (error) {
  if (error instanceof APIError) console.error(error.status, error.body);
  else if (error instanceof NetworkError) console.error('Network error', error);
  else throw error;
}
```

A hook's `error` is typed `ApiClientError` (`APIError | NetworkError | APIConfigurationError | ZodError |
DOMException`), exported from `@djangocfg/api`.

Generated operations parse successful responses with Zod before returning
them. Use the generated MSW handlers from `@djangocfg/api/mocks` (or the
target's MSW barrel) in tests and Storybook; do not hand-write a second REST
mock contract.

## Python Clients

### Installation

A Python target is written into the `path` of its `Target` in `generation.py` (the paths below stand for that directory).

<Callout type="info">
**Group Organization**

The client is built by `openapi-python-client`: Pydantic models, one subclient per tag, async support.

</Callout>

#### Install Locally

```bash
pip install -e path/to/python/target

# Or add to requirements.txt
echo "-e path/to/python/target" >> requirements.txt
```

#### Publish to PyPI

Package and publish:

```bash
cd path/to/python/target
python -m build
python -m twine upload dist/*
```

### Basic Usage

```python
from trading import Client
from trading.api.default import (
    list_wallets,
    get_wallet,
    create_order
)
from trading.models import OrderCreate

# Initialize client
client = Client(base_url="https://api.cryptoplatform.com")
client = client.with_headers({
    "Authorization": "Bearer access-token"
})

# Synchronous API calls
wallets = list_wallets.sync(client=client)
print(f"Found {len(wallets.results)} wallets")

wallet = get_wallet.sync(id="btc-wallet-123", client=client)
print(f"Wallet: {wallet.currency} - {wallet.balance}")

# Create order
order_data = OrderCreate(
    symbol="BTC/USDT",
    side="buy",
    amount=0.1,
    price=45000
)
new_order = create_order.sync(
    client=client,
    json_body=order_data
)
print(f"Created order: {new_order.id}")
```

### Async Usage

```python
import asyncio
from trading import Client
from trading.api.default import (
    list_wallets,
    create_order
)

async def main():
    client = Client(base_url="https://api.cryptoplatform.com")
    client = client.with_headers({
        "Authorization": "Bearer access-token"
    })

    # Async API calls
    wallets = await list_wallets.asyncio(client=client)
    print(f"Found {len(wallets.results)} wallets")

    new_order = await create_order.asyncio(
        client=client,
        json_body={"symbol": "ETH/USDT", "side": "buy", "amount": 1}
    )
    print(f"Created: {new_order.id}")

# Run async code
asyncio.run(main())
```

### Multiple Groups

```python
# Import clients from different groups
from core import Client as CoreClient
from trading import Client as TradingClient
from market import Client as MarketClient

# Initialize clients with shared authentication
base_url = "https://api.cryptoplatform.com"
headers = {"Authorization": "Bearer access-token"}

core = CoreClient(base_url=base_url).with_headers(headers)
trading = TradingClient(base_url=base_url).with_headers(headers)
market = MarketClient(base_url=base_url).with_headers(headers)

# Use each client
from core.api.default import list_users, get_user
from trading.api.default import list_wallets, list_orders
from market.api.default import get_prices

users = list_users.sync(client=core)
wallets = list_wallets.sync(client=trading)
orders = list_orders.sync(client=trading, status="open")
prices = get_prices.sync(client=market, symbols=["BTC", "ETH"])
```

### Django Integration

```python
# views.py
from django.http import JsonResponse
from trading import Client
from trading.api.default import list_wallets

def get_user_wallets(request):
    """Get wallets for current user"""
    # Create API client
    client = Client(base_url="https://api.cryptoplatform.com")
    client = client.with_headers({
        "Authorization": f"Bearer {request.user.access_token}"
    })

    # Fetch wallets
    try:
        wallets = list_wallets.sync(
            client=client,
            user_id=request.user.id
        )
        return JsonResponse({
            'wallets': [wallet.dict() for wallet in wallets.results]
        })
    except Exception as e:
        return JsonResponse({'error': str(e)}, status=500)
```

### FastAPI Integration

```python
from fastapi import FastAPI, Depends
from trading import Client
from trading.api.default import list_wallets, list_orders

app = FastAPI()

def get_api_client():
    """Dependency to get API client"""
    client = Client(base_url="https://api.cryptoplatform.com")
    return client.with_headers({
        "Authorization": "Bearer service-token"
    })

@app.get("/wallets")
async def get_wallets(client: Client = Depends(get_api_client)):
    """Get all wallets"""
    wallets = await list_wallets.asyncio(client=client)
    return {"wallets": [wallet.dict() for wallet in wallets.results]}

@app.get("/orders")
async def get_orders(status: str = "open", client: Client = Depends(get_api_client)):
    """Get orders by status"""
    orders = await list_orders.asyncio(client=client, status=status)
    return {"orders": [order.dict() for order in orders.results]}
```

## Swift Clients (iOS/macOS)

Django-CFG generates Swift clients using Apple's official `swift-openapi-generator`. This produces native Swift code with async/await support.

<Callout type="info">
**External Generator**

Swift generation requires `swift-openapi-generator` to be installed:
```bash
brew install swift-openapi-generator
```
</Callout>

### Installation

Generated Swift clients are written into the `path` of the Swift `Target` in `generation.py`.

#### Add to Xcode Project

1. Copy the generated directory to your iOS project
2. Add files to your target in Xcode
3. Install OpenAPIRuntime via SPM:

```swift

    .package(url: "https://github.com/apple/swift-openapi-runtime", from: "1.0.0"),
    .package(url: "https://github.com/apple/swift-openapi-urlsession", from: "1.0.0"),
]
```

### Basic Usage

```swift
import OpenAPIRuntime
import OpenAPIURLSession
import TradingAPI  // Generated client

// Initialize client
let client = Client(
    serverURL: URL(string: "https://api.cryptoplatform.com")!,
    transport: URLSessionTransport()
)

// List wallets (async/await)
Task {
    do {
        let response = try await client.walletsList()
        switch response {
        case .ok(let okResponse):
            let wallets = try okResponse.body.json
            for wallet in wallets.results {
                print("\(wallet.currency): \(wallet.balance)")
            }
        case .undocumented(let statusCode, _):
            print("Unexpected status: \(statusCode)")
        }
    } catch {
        print("Error: \(error)")
    }
}
```

### Authentication

```swift
// Add Bearer token via middleware
struct AuthMiddleware: ClientMiddleware {
    let token: String

    func intercept(
        _ request: HTTPRequest,
        body: HTTPBody?,
        baseURL: URL,
        operationID: String,
        next: (HTTPRequest, HTTPBody?, URL) async throws -> (HTTPResponse, HTTPBody?)
    ) async throws -> (HTTPResponse, HTTPBody?) {
        var modifiedRequest = request
        modifiedRequest.headerFields[.authorization] = "Bearer \(token)"
        return try await next(modifiedRequest, body, baseURL)
    }
}

// Use with client
let client = Client(
    serverURL: URL(string: "https://api.cryptoplatform.com")!,
    transport: URLSessionTransport(),
    middlewares: [AuthMiddleware(token: accessToken)]
)
```

### SwiftUI Integration

```swift
import SwiftUI

struct WalletListView: View {
    @State private var wallets: [Wallet] = []
    @State private var isLoading = true
    @State private var error: Error?

    private let client = Client(
        serverURL: URL(string: "https://api.cryptoplatform.com")!,
        transport: URLSessionTransport()
    )

    var body: some View {
        Group {
            if isLoading {
                ProgressView()
            } else if let error = error {
                Text("Error: \(error.localizedDescription)")
            } else {
                List(wallets, id: \.id) { wallet in
                    HStack {
                        Text(wallet.currency)
                        Spacer()
                        Text(wallet.balance)
                    }
                }
            }
        }
        .task {
            await loadWallets()
        }
    }

    private func loadWallets() async {
        do {
            let response = try await client.walletsList()
            if case .ok(let okResponse) = response {
                wallets = try okResponse.body.json.results
            }
            isLoading = false
        } catch {
            self.error = error
            isLoading = false
        }
    }
}
```

### Error Handling

```swift
do {
    let response = try await client.ordersCreate(
        body: .json(.init(
            symbol: "BTC/USDT",
            side: .buy,
            amount: 0.1,
            price: 45000
        ))
    )

    switch response {
    case .ok(let okResponse):

        print("Order created: \(order.id)")
    case .badRequest(let errorResponse):
        let error = try errorResponse.body.json

    case .unauthorized:
        print("Not authenticated")
    case .undocumented(let statusCode, _):
        print("Unexpected status: \(statusCode)")

}
```

## Type Safety

### TypeScript Types

Request/response types and Zod schemas are generated together. Import them
from the model barrel and use the operation barrel for calls:

```typescript
import { cryptoCoinsList } from '@api/generated/endpoints';
import { CoinListing } from '@api/generated/models';

const coins: Awaited<ReturnType<typeof cryptoCoinsList>> =
  await cryptoCoinsList({ page: 1 });

const firstCoin: CoinListing | undefined = coins.results[0];
// Successful responses have already passed the generated Zod schema.
```

### Python Types

Generated Python clients use `attrs` classes for type safety:

```python
from cfg_support.models import Ticket, TicketCreate

# Type hints work in IDEs
def process_ticket(ticket: Ticket) -> None:
    print(ticket.id)        # ✓ Valid
    print(ticket.title)     # ✓ Valid
    print(ticket.invalid)   # ❌ IDE error

# Pydantic-style validation
new_ticket = TicketCreate(
    title="Test",
    description="Test ticket",
    priority="high"
)
# Invalid data raises validation error
invalid = TicketCreate(priority="invalid")  # ❌ ValidationError
```

## Best Practices

### 1. Keep one runtime boundary

- Import operations and models from generated barrels.
- Import `auth`, `djangoFetch`, `APIError`, and `NetworkError` from `@djangocfg/api`.
- Do not add a per-group client, token store, refresh handler, or hand-written fetch wrapper.

### 2. Use generated query infrastructure

- Mount one `ApiQueryProvider` from `@djangocfg/api/query` per app.
- Use generated `get*QueryOptions` for SSR prefetching.
- Use generated `get*QueryKey` for invalidation; never invent string keys.

### 3. Keep mocks next to the contract

Use generated MSW handlers from `@djangocfg/api/mocks` or the target's MSW
barrel in tests and Storybook. Do not edit generated handlers to fix a schema
problem; fix the Django serializer/OpenAPI metadata and regenerate.

### 4. Retry only at the query policy boundary

```python
import backoff
from httpx import HTTPStatusError

@backoff.on_exception(
    backoff.expo,
    HTTPStatusError,
    max_tries=3,
    giveup=lambda e: e.response.status_code < 500
)
def fetch_tickets(client):
    """Fetch tickets with retry logic"""
    return list_tickets.sync(client=client)
```
